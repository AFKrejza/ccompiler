expression -> term -> factor naming convention:
expression for loose-binding + -
term for tighter-binding like * /
factor for things like parentheses that explicitly group things or things that have no operators.

using EBNF (more or less):


Nonterminals are wrapped in <>
Individual tokens are in ""
[...] contains optional elements (zero or one time)
{...} states repetition (zero or more times)
(...) groups choices or sequences together

Terminals: type, IDENTIFIER, INTEGER

2026-09-19 parser grammar:

<program>		= <function>
<function>		= "int" IDENTIFIER "(" <paramList> ")" <functionBody>
<paramList>		= [ <parameter> { "," <parameter> } ]
<parameter>		= "int" IDENTIFIER
<functionBody>	=  "{" { <statement> } "}"
<statement>		= <ret> | <declaration> | <assignment>
<ret>			= "return" <expression>
<declaration>	= "int" IDENTIFIER [ "=" <expression> ]
<expression>	= <logicalOr>
<logicalOr>		= <logicalAnd>	{ "||" <logicalAnd> }
<logicalAnd>	= <equality>	{ "&&" <equality> }
<equality>		= <relational>	{ ( "==" | "!=") <relational> }
<relational>	= <additive>	{ ( "<" | "<=" | ">" | ">=" ) <additive> }
<additive>		= <term>		{ ("+" | "-") <term> }
<term>			= <unary>		{ "*" <unary> }
<unary>			= <unop> <unary> | <factor>
<unop>			= "-"
<factor>		= INTEGER | IDENTIFIER | "(" <expression> ")"
